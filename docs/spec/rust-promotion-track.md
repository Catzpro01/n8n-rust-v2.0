# Rust Promotion Track

Each non-native capability is classified as remote adapter, isolated local adapter, native candidate, native preview, or native preferred. Promotion requires shared conformance fixtures, equivalent error and retry semantics, performance and memory evidence, migration tests, security review, and a retained fallback until the native implementation is proven.

Initial native priorities are HTTP and webhook handling, streaming parsers, expression evaluation, crawl frontier and deduplication, HTML and structured extraction, OAuth and protocol clients, common data transforms, MCP, OpenAPI connectors, and high-volume n8n core nodes.

Full npm and CPython ecosystems remain compatibility fallbacks. Chromium, Firefox, Playwright-managed browsers, Camoufox, hosted Firecrawl, Bright Data, Oxylabs, and external agent products are integrated through Rust protocol adapters; their third-party internals are not falsely described as Rust-native.
